파이썬 코인 자동매매 시작 가이드

게만아의 파이썬 코인 자동매매 코드는 업비트·빗썸·코인원·바이낸스를 지원합니다. 주식처럼 한 전략 파일에서 Broker를 바꿔 끼우는 구조가 아니라, 거래소별 API 특성에 맞춰 각각 별도의 공통모듈과 연결 구조를 구현합니다. 실시간 호가창 초단타보다 REST API 중심으로 잔고·포지션·시세·주문을 처리합니다.

1. 현물과 선물을 먼저 구분합니다

현물은 보유 수량과 평균단가 중심으로 생각할 수 있지만, 선물은 롱·숏 포지션, 레버리지, 증거금 방식, 청산 위험, 포지션 모드 같은 추가 상태가 있습니다.

2. REST API 중심으로 조회와 주문을 연결합니다

게만아의 코인 자동매매는 실시간 호가창이나 초단타 처리를 전제로 하지 않고 REST API 중심으로 구성합니다. 잔고, 포지션, 현재가, 과거 캔들, 주문과 설정 정보를 전략 실행 주기에 맞춰 조회하고 처리합니다.

3. 코인은 거래소별로 따로 구현합니다

주식 쪽은 같은 전략 파일에서 증권사 Broker를 전환하는 구조를 활용할 수 있지만, 게만아의 코인 코드는 현재 그런 단일 Adapter 전환 방식이 아닙니다.

업비트, 빗썸, 코인원, 바이낸스 각각에 맞는 공통모듈과 API 연결부를 별도로 구현합니다. 예를 들어 myUpbit, myBithumb, myCoinone, myBinance처럼 거래소별 공통모듈이 따로 있고, 해당 거래소용 전략·주문 코드가 그 모듈을 사용합니다.

이렇게 나누는 이유는 거래소마다 인증, symbol 체계, 최소주문금액, 수량 정밀도, 현물·선물 규칙과 주문 파라미터가 다르기 때문입니다. 억지로 하나의 Adapter에 모든 차이를 숨기기보다 거래소별 구현을 분리해 명확하게 관리하는 방향입니다.

4. API Key 권한을 최소화합니다

자동매매에 필요한 거래 권한만 부여하고 출금 권한은 가능하면 비활성화합니다. API Key와 Secret은 공개 GitHub, 영상, 로그, 스크린샷에 노출하지 않습니다.

5. 백테스트와 실전의 차이

24시간 시장이라도 API 장애, 서버 재시작, 펀딩비, 거래수수료, 슬리피지, 레버리지, 강제청산, 거래소별 시세차이가 실전 결과에 영향을 줍니다. 선물 전략일수록 실전 검증 단계가 중요합니다.

6. 주문 전 안전장치

  • 실행 플래그 OFF 상태에서 신호와 수량 출력
  • 최소주문금액·수량단위 검사
  • 현재 포지션과 주문 방향 재확인
  • 중복 주문 방지
  • API 오류·시간초과 재시도 정책
  • 실제 운용 전 소액 테스트

바이낸스는 CCXT를 활용합니다

게만아의 바이낸스 코드는 Binance REST API를 직접 처음부터 감싸는 방식이 아니라, Python에서 여러 거래소 API를 공통 형태로 다룰 수 있는 CCXT 라이브러리를 활용합니다.

따라서 바이낸스 관련 구현을 확장하거나 확인할 때는 Binance 문서만 보는 것보다 CCXT 공식 문서와 현재 사용 중인 myBinance 구조를 함께 확인하는 것이 실제 코드와 더 잘 맞습니다.

7. 코인에서도 투자 철학은 같습니다

코인의 변동성이 더 크다고 해서 미래 가격을 더 많이 예측하려 하지는 않습니다. 전략을 과거 데이터로 검증하고, 손실과 MDD를 감당할 수 있는 크기로 비중을 정하며, 조건이 바뀌면 정해진 규칙대로 대응합니다.

자동매매는 예측 엔진이 아니라 기준 실행기에 가깝습니다. 사람이 세운 규칙을 24시간 시장에서도 빠뜨리지 않고 반복하는 것이 핵심입니다.
