게만아 코드 + AI 확장 가이드

게만아 코드는 AI와 함께 계속 확장할 수 있습니다

게만아 콘텐츠에서 제공하는 파이썬 코드는 주식·코인 전략, 백테스트, 실제 자동매매 봇, 증권사·거래소 공통모듈, 알림·모니터링 같은 보조시스템까지 모두 AI와 함께 이해하고 수정·확장할 수 있습니다. 완성된 코드를 그대로 활용할 수도 있고, 자신의 아이디어에 맞게 조건과 기능을 더해 계속 발전시킬 수도 있습니다.

어디까지 AI로 확장할 수 있나요?

코드 영역확장 예시
전략 코드매수·매도 조건, 리밸런싱 규칙, 비중, 손절·추세 조건, RSI·스토캐스틱·볼린저 밴드 같은 보조지표 추가
백테스트검증 기간·종목·자산 변경, 수수료·슬리피지 반영, 성과지표 추가, 전략 간 비교
자동매매 봇운용 조건, 주문 시점, 계좌별 설정, 로그·알림·예외처리, 실행 흐름 변경
증권사·거래소 공통모듈개인적으로 필요한 추가 조회·주문 기능, 새로운 증권사·거래소 연결
보조시스템서버 자동 실행, 메시지 알림, 상태 모니터링, 데이터 저장·리포트 기능
코인 코드업비트·빗썸·코인원·바이낸스의 전략·백테스트·봇·공통모듈도 같은 방식으로 수정·확장

완성된 코드이면서, 동시에 나만의 시스템을 만드는 출발점입니다

예를 들어 기존 전략에 RSI 필터를 더하고 싶거나, 백테스트에 새로운 성과지표를 추가하고 싶거나, 자동매매 봇의 알림·예외처리를 바꾸고 싶다면 해당 코드를 AI에게 읽힌 뒤 현재 구조를 유지하면서 필요한 부분만 수정하도록 요청할 수 있습니다.

주식이든 코인이든 원리는 같습니다. 맨땅에서 시스템 전체를 다시 만드는 것보다 이미 동작 구조와 데이터 흐름이 잡혀 있는 코드를 기준으로 확장하는 편이 훨씬 빠르고 검토하기도 쉽습니다.

가장 효율적인 AI 활용 순서

  1. 내가 원하는 것과 가장 가까운 기존 코드를 선택합니다.
  2. AI에게 먼저 현재 코드의 흐름을 설명하게 합니다. 어떤 조건에서 무엇을 계산하고 주문하는지 이해부터 시킵니다.
  3. 바꾸고 싶은 내용을 자연어로 구체적으로 요청합니다. “RSI가 30 이하일 때만 진입”, “백테스트에 거래비용 추가”처럼 원하는 결과를 명확히 합니다.
  4. 전체를 다시 쓰지 말고 기존 구조를 최대한 유지하도록 요청합니다. 변경 범위가 작을수록 검토와 오류 추적이 쉽습니다.
  5. 백테스트·로그·조회 결과부터 확인합니다. 전략 변경이라면 먼저 과거 데이터에서 동작을 확인합니다.
  6. 실제 주문은 가장 마지막에 확인합니다. 계좌·종목·수량·거래시간을 다시 확인하고 작은 범위부터 적용합니다.

AI에게 이렇게 요청해볼 수 있습니다

첨부한 파일은 제가 실제로 사용하려는 게만아 파이썬 코드입니다.

먼저 이 코드의 전체 흐름과 핵심 조건을 설명해주세요.
그 다음 아래 기능을 기존 구조를 최대한 유지하면서 추가해주세요.

[원하는 변경 내용]

조건:
1. 기존 기능은 가능한 한 유지
2. 수정한 위치와 이유를 설명
3. 임의로 전체 구조를 새로 만들지 않기
4. 오류가 날 수 있는 부분은 별도로 알려주기
5. 실제 주문과 관련된 변경은 특히 명확히 표시
6. 수정 후 확인해야 할 테스트 방법도 제시

전략, 백테스트, 자동매매 봇, 공통모듈, 보조시스템 모두 기본적으로 같은 방식으로 접근하면 됩니다.

예시: 공통모듈에 없는 증권사 API 기능을 추가하고 싶다면

먼저, 게만아 패키지와 슈퍼 이동평균 전략을 일반적으로 운용하기 위해 사용자가 증권사 API 문서를 보며 기능을 추가할 필요는 거의 없습니다. 실제 전략에서 사용하는 조회·주문 등 핵심 API 기능은 이미 구현되어 있고, 증권사 문서에 나오는 모든 기능을 구현하지 않아도 자동매매 시스템 운용에는 문제가 없습니다.

다만 새 주문유형, 추가 조회 기능, 새로운 상품처럼 현재 코드에 없는 기능을 개인적으로 더 사용하고 싶다면 그때는 기존 공통모듈과 증권사 공식 API 문서를 AI에게 함께 제공해 필요한 함수만 추가할 수 있습니다.

현재 공통모듈에는 [원하는 API 기능]이 없습니다.
첨부한 기존 공통모듈의 함수 스타일을 유지하면서
아래 증권사 공식 API 문서를 기준으로 새 함수만 추가해주세요.
공식 문서에 없는 endpoint나 필드는 추측하지 마세요.

즉, 공식 API 문서는 기존 시스템을 쓰기 위한 필수 과정이 아니라 필요할 때 확장하기 위한 참고자료라고 생각하면 됩니다.

개인적으로는 Cursor를 주로 사용합니다

게만아도 AI를 적극적으로 활용하며 개인적으로는 Cursor를 주로 사용합니다. 프로젝트 파일을 함께 열어두고 여러 코드의 관계를 AI가 참고하게 하기 편하기 때문입니다.

다만 Cursor가 필수라는 의미는 아닙니다. ChatGPT, Claude 등 자신에게 익숙한 AI 도구를 사용해도 됩니다. 핵심은 좋은 기존 코드 + 명확한 요청 + 변경 결과의 검증입니다.

보안은 AI보다 먼저

  • 발급받은 API 키·Secret·접근토큰은 비밀번호와 같은 정보입니다. AI에게 코드를 보여줄 때도 실제 값은 지우거나 임의의 값으로 바꿔주세요.
  • 계좌번호 등 개인 정보가 필요한 예시도 일부를 가리거나 임의의 값으로 바꿔주세요.
  • AI가 수정한 주문 코드는 조회·로그부터 확인하고 주문 활성화는 마지막에 합니다.

바이브 코딩의 진짜 지름길은 ‘좋은 출발 코드’입니다

AI에게 처음부터 자동매매 시스템 전체를 만들어달라고 할 수도 있습니다. AI가 없던 시절보다 훨씬 빠르게 만들 수 있는 것도 사실입니다. 그러나 실제 운용 단계에서는 전략 검증, 데이터 처리, API 연결, 주문·체결, 예외처리, 서버 실행 같은 시행착오가 계속 생깁니다.

이미 실제 전략에서 사용해온 코드를 출발점으로 AI와 수정·확장하면 그 시행착오를 크게 줄일 수 있습니다. 게만아 코드는 완성된 결과물인 동시에, 자신만의 시스템으로 계속 발전시킬 수 있는 코드 베이스입니다.

AI 시대의 자동매매 판단 기준: 소스 코드를 직접 확인할 수 있는가?

AI로 자동매매 서비스를 만드는 문턱이 낮아질수록 겉으로는 비슷한 서비스도 늘어날 수 있습니다. 이때 중요한 기준 중 하나는 내가 실제 소스 코드를 받아 매매 조건과 주문 로직을 확인하고, 필요하면 직접 또는 AI와 함께 수정할 수 있는가입니다.

코드를 볼 수 있다고 오류가 절대 없다는 뜻은 아닙니다. 하지만 설명만 믿어야 하는 블랙박스와, 내가 직접 확인·검증·통제할 수 있는 시스템은 분명히 다릅니다.

중요

AI는 수정과 개발 속도를 크게 높여주지만 결과의 정확성을 자동으로 보장하지는 않습니다. 전략 변경은 백테스트와 데이터로, API 변경은 공식 문서와 실제 응답으로, 주문 변경은 충분한 테스트로 확인한 뒤 적용하세요.
