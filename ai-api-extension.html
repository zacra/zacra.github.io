게만아 공통모듈 확장 가이드

공통모듈에 없는 증권사 API 기능, AI로 추가할 수 있습니다

게만아 공통모듈은 증권사의 모든 API 기능을 미리 구현하는 범용 SDK가 아닙니다. 실제 자동매매 전략에서 필요한 기능을 중심으로 구현하고, 개인적으로 추가 기능이 필요할 때 공식 API 문서와 기존 코드를 바탕으로 확장하는 방식을 권합니다.

먼저 세 가지 범위를 구분하세요

구분목적구현 범위
무료 Starter자동매매 전체 흐름 입문인증, 계좌·보유종목·현재가, 기본 데이터, 리밸런싱, 기본 주문 등 핵심 Lite 기능
정식 공통모듈게만아 패키지·전략 실제 운용Starter보다 넓고 실제 전략에서 사용해온 조회·주문·계좌 기능 중심
증권사 공식 Open API증권사가 외부에 제공하는 전체 개발 인터페이스게만아가 현재 사용하지 않는 조회·주문·상품 기능까지 더 많은 명세가 존재할 수 있음

“함수가 없다”와 “API가 지원되지 않는다”는 다른 말입니다

게만아 공통모듈에 어떤 함수가 없더라도 해당 증권사의 공식 Open API에서 기능을 제공하고 있다면 새 함수를 추가할 수 있습니다. 현재 함수가 없는 이유는 대개 게만아 패키지나 슈퍼 이동평균 전략에서 실제로 사용할 필요가 없었기 때문입니다.

가장 효율적인 확장 순서

  1. 기존 공통모듈을 준비합니다. 인증, 헤더, 응답 파싱, 에러 처리, 함수명 스타일을 AI가 그대로 참고할 수 있게 합니다.
  2. 증권사 공식 API 문서에서 원하는 기능을 찾습니다. 엔드포인트와 요청·응답 필드를 확인합니다.
  3. 기존 코드 + 공식 문서 링크를 AI에 같이 줍니다. “공식 문서에 없는 값은 추측하지 말라”고 명시합니다.
  4. 기존 함수는 건드리지 말고 새 함수만 추가하도록 요청합니다. 변경 범위를 작게 만들수록 검토하기 쉽습니다.
  5. 조회 함수부터 실제 응답을 검증합니다. 주문 관련 기능은 계좌·종목·수량·거래시간을 다시 확인한 뒤 가장 마지막에 테스트합니다.
  6. AI가 만든 코드도 사람이 검토합니다. 특히 증권사 TR/endpoint, 파라미터명, 매수·매도 구분과 계좌번호 처리는 반드시 직접 확인합니다.

AI에게 이렇게 요청해보세요

첨부한 파일은 제가 실제로 사용하는 증권사 공통모듈입니다.

아래 공식 API 문서를 기준으로
[원하는 기능] 함수를 하나 추가해주세요.

공식 API 문서:
[해당 증권사 공식 문서 URL]

조건:
1. 기존 인증/헤더/응답처리 구조를 최대한 재사용
2. 기존 함수는 수정하지 않기
3. 기존 함수명과 리턴 형식 스타일 유지
4. 공식 문서에 없는 endpoint나 필드는 추측하지 않기
5. 먼저 구현 계획을 짧게 설명한 뒤 코드 제시
6. 실제 주문 함수라면 위험한 파라미터를 별도로 설명
7. 사용 예시도 함께 제공

필요하다면 “이 함수를 기존 전략 코드 어디에서 호출하면 되는가?”까지 이어서 물어볼 수 있습니다.

개인적으로는 Cursor를 주로 사용합니다

요즘 바이브 코딩은 코드를 직접 운영하는 사람에게 점점 중요한 도구가 되고 있습니다. 게만아도 AI를 적극적으로 활용하며, 개인적으로는 Cursor를 주로 사용합니다.

VS Code 계열의 코드 편집 환경에서 프로젝트 파일을 열어두고 AI에게 코드 구조를 설명시키거나, 오류를 찾고, 기존 로직을 유지한 채 필요한 함수를 추가하도록 요청하기 편하기 때문입니다.

다만 Cursor가 필수라는 의미는 아닙니다. ChatGPT, Claude 등 자신에게 익숙한 AI 도구를 사용해도 됩니다. 핵심은 좋은 기존 코드 + 최신 공식 API 문서 + 명확한 요청 + 최종 검증입니다.

제가 실제로 쓰는 Cursor 활용법 보기

Cursor의 요금제, 제공 모델, UI와 프로모션은 바뀔 수 있으므로 최신 내용은 해당 서비스의 공식 안내를 확인하세요. 연결된 카페 글에는 레퍼럴 링크가 포함될 수 있으며 그 경우 작성자에게 혜택이 제공될 수 있습니다.

7개 증권사 공식 API 문서

AI가 API 명세를 추측하게 하지 말고 아래 공식 문서를 함께 제공하는 것을 권합니다.

  • 한국투자증권 KIS Developers
  • LS증권 Open API
  • 키움증권 REST API
  • 토스증권 Open API
  • KB증권 Open API
  • NH투자증권 PLUG
  • DB증권 Open API

코인 거래소까지 포함한 전체 공식 출처 보기 →

보안은 AI보다 먼저

  • App Key, Secret, 접근토큰을 AI 채팅이나 공개 저장소에 그대로 넣지 않습니다.
  • 계좌번호가 필요한 예시는 마스킹하거나 샘플 값으로 바꿉니다.
  • AI가 만든 주문 코드는 조회·로그부터 확인하고 주문 활성화는 마지막에 합니다.
  • 공식 문서와 실제 API 응답이 다르면 실제 최신 명세와 증권사 공지를 우선합니다.

패키지 코드 + AI가 강력한 이유

완전히 빈 화면에서 새 시스템을 만드는 것보다, 이미 인증·계좌·시세·주문 구조가 잡혀 있는 코드를 출발점으로 AI에게 필요한 기능만 확장시키는 편이 훨씬 빠릅니다. 그래서 게만아 패키지를 단순한 완제품이 아니라 AI와 함께 계속 발전시킬 수 있는 코드 자산으로도 활용할 수 있습니다.

중요

AI는 코드를 빠르게 만들 수 있지만 증권사 API의 정확성을 보장하는 정본은 아닙니다. 증권사 공식 문서와 실제 응답을 기준으로 검증하고, 특히 주문 기능은 충분한 확인 뒤 적용해야 합니다.
