게만아 공통모듈 확장 가이드

공통모듈에 없는 증권사 API 기능, AI로 추가할 수 있습니다

게만아 공통모듈은 증권사의 모든 API 기능을 미리 구현하는 범용 SDK가 아닙니다. 실제 자동매매 전략에서 필요한 기능을 중심으로 구현하고, 개인적으로 추가 기능이 필요할 때 공식 API 문서와 기존 코드를 바탕으로 확장하는 방식을 권합니다.

먼저 세 가지 범위를 구분하세요

구분목적구현 범위
무료 Starter자동매매 전체 흐름 입문인증, 계좌·보유종목·현재가, 기본 데이터, 리밸런싱, 기본 주문 등 핵심 Lite 기능
정식 공통모듈게만아 패키지·전략 실제 운용Starter보다 넓고 실제 전략에서 사용해온 조회·주문·계좌 기능 중심
증권사 공식 Open API증권사가 외부에 제공하는 전체 개발 인터페이스게만아가 현재 사용하지 않는 조회·주문·상품 기능까지 더 많은 명세가 존재할 수 있음

“함수가 없다”와 “API가 지원되지 않는다”는 다른 말입니다

게만아 공통모듈에 어떤 함수가 없더라도 해당 증권사의 공식 Open API에서 기능을 제공하고 있다면 새 함수를 추가할 수 있습니다. 현재 함수가 없는 이유는 대개 게만아 패키지나 슈퍼 이동평균 전략에서 실제로 사용할 필요가 없었기 때문입니다.

멀티브로커 구조가 AI 확장에도 유리합니다

게만아 주식 전략은 Broker·Market·계좌를 분리하고 Common/API Helper의 공통 함수 규격을 사용합니다. 그래서 새 증권사나 새 기능을 추가할 때도 완전히 새로운 전략 파일을 만드는 것보다 기존 공통 함수의 입력·리턴 스타일을 기준으로 새 함수를 맞추는 방식으로 접근하기 쉽습니다.

가장 효율적인 확장 순서

  1. 기존 공통모듈을 준비합니다. 인증, 헤더, 응답 파싱, 에러 처리, 함수명 스타일을 AI가 참고할 수 있게 합니다.
  2. 증권사 공식 API 문서에서 원하는 기능을 찾습니다.
  3. 기존 코드 + 공식 문서 링크를 AI에 같이 줍니다. 공식 문서에 없는 값은 추측하지 말라고 명시합니다.
  4. 기존 함수는 건드리지 말고 새 함수만 추가하도록 요청합니다.
  5. 조회 함수부터 실제 응답을 검증합니다. 주문 기능은 마지막에 테스트합니다.
  6. AI가 만든 코드도 사람이 검토합니다. endpoint, 파라미터, 매수·매도 구분과 계좌 처리는 반드시 직접 확인합니다.

AI에게 이렇게 요청해보세요

첨부한 파일은 제가 실제로 사용하는 증권사 공통모듈입니다.

아래 공식 API 문서를 기준으로
[원하는 기능] 함수를 하나 추가해주세요.

조건:
1. 기존 인증/헤더/응답처리 구조를 최대한 재사용
2. 기존 함수는 수정하지 않기
3. 기존 함수명과 리턴 형식 스타일 유지
4. 공식 문서에 없는 endpoint나 필드는 추측하지 않기
5. 먼저 구현 계획을 짧게 설명한 뒤 코드 제시
6. 실제 주문 함수라면 위험한 파라미터를 별도로 설명
7. 사용 예시도 함께 제공

개인적으로는 Cursor를 주로 사용합니다

게만아도 AI를 적극적으로 활용하며 개인적으로는 Cursor를 주로 사용합니다. 다만 Cursor가 필수는 아니며 ChatGPT, Claude 등 익숙한 도구를 사용해도 됩니다. 핵심은 좋은 기존 코드 + 최신 공식 API 문서 + 명확한 요청 + 최종 검증입니다.

보안은 AI보다 먼저

  • App Key, Secret, 접근토큰을 AI 채팅이나 공개 저장소에 그대로 넣지 않습니다.
  • 계좌번호가 필요한 예시는 마스킹하거나 샘플 값으로 바꿉니다.
  • AI가 만든 주문 코드는 조회·로그부터 확인하고 주문 활성화는 마지막에 합니다.
  • 공식 문서와 실제 API 응답이 다르면 최신 명세와 증권사 공지를 우선합니다.

바이브 코딩의 진짜 지름길은 ‘좋은 출발 코드’입니다

AI에게 처음부터 자동매매 시스템 전체를 만들어달라고 할 수도 있습니다. 하지만 실제 운용 단계에서는 인증, 계좌, 시세, 주문, 체결, 예외처리, 서버 실행과 같은 문제를 계속 만나게 됩니다. 빈 화면에서 AI와 함께 시행착오를 반복하는 것보다, 이미 실제 전략에서 사용해온 구조를 AI가 읽게 하고 필요한 부분만 바꾸는 편이 훨씬 빠릅니다.

게만아 코드는 단순한 완제품이라기보다 AI와 함께 계속 수정·확장할 수 있는 실전 코드 베이스라는 점에 가치가 있습니다.

AI 시대의 자동매매 판단 기준: 코드를 직접 확인할 수 있는가?

AI로 만든 자동매매 서비스가 늘어날수록 시스템이 무엇을 하는지 사용자가 볼 수 없는 ‘블랙박스’ 문제도 커집니다. 게만아가 중요하게 보는 기준은 단순합니다. 소스 코드를 직접 받아 매매 조건과 주문 로직을 확인하고, 자신의 환경에서 실행하며, 필요하면 직접 또는 AI와 함께 수정할 수 있는가입니다.

코드를 볼 수 있다고 오류가 절대 없다는 뜻은 아닙니다. 그러나 확인할 수 없는 서비스를 믿는 것과, 내가 직접 검토·검증·통제할 수 있는 시스템을 운용하는 것은 다릅니다.

중요

AI는 코드를 빠르게 만들 수 있지만 증권사 API의 정확성을 보장하는 정본은 아닙니다. 증권사 공식 문서와 실제 응답을 기준으로 검증하고, 특히 주문 기능은 충분한 확인 뒤 적용해야 합니다.
