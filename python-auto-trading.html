파이썬 자동매매 시작 가이드

주식이든 코인이든 자동매매의 핵심 구조는 비슷합니다. 전략 정의 → 데이터 → 백테스트 → API 연결 → 계좌/포지션 확인 → 주문 → 상태관리를 단계적으로 연결합니다.

자동화보다 먼저 필요한 것은 기준입니다

자동매매의 목적은 미래를 더 잘 맞히는 것이 아니라, 미리 검증한 기준을 감정에 흔들리지 않고 반복하는 것입니다. 그래서 게만아는 수익률 하나보다 MDD와 지속 가능성을 먼저 보고, 예측보다 대응 가능한 규칙을 만든 뒤 자동화합니다.

게만아 시스템 투자 철학 →

1. 매매 아이디어를 숫자와 조건으로 바꿉니다

“오를 것 같다”는 판단은 자동화하기 어렵습니다. 매수·매도 조건, 투자비중, 손절·익절, 리밸런싱 조건을 코드로 표현할 수 있을 정도로 구체화해야 합니다.

2. 과거 데이터로 검증합니다

수익률만 보지 말고 MDD, 거래횟수, 수수료, 슬리피지, 구간별 성과, 파라미터 민감도를 함께 확인합니다.

백테스트 체크리스트 →

3. 시장에 맞는 API를 선택합니다

주식·ETF

증권사 Open API를 통해 시세·잔고·보유종목·주문을 연결합니다. 공통 인터페이스로 작성된 전략은 증권사·시장·계좌를 선택하는 멀티브로커 구조로 확장할 수 있습니다.

멀티 증권사 API →

코인

거래소 REST API를 통해 현물·선물 시세, 잔고, 포지션과 주문을 연결합니다.

코인 자동매매 →

구조는 시장별로 다릅니다

주식은 동일 전략 파일에서 증권사 브로커를 전환하는 멀티브로커 구조를 활용하지만, 코인은 업비트·빗썸·코인원·바이낸스를 거래소별 공통모듈로 각각 구현합니다.

주식·코인 구조 차이 →

4. 조회 기능부터 확인합니다

  1. 인증·토큰 발급
  2. 잔고/포지션 조회
  3. 보유종목/보유코인 조회
  4. 현재가·호가·과거 데이터 조회
  5. 전략 신호 계산
  6. 주문 수량 계산
  7. 마지막에 실제 주문

5. 실제 주문은 가장 마지막 단계입니다

처음부터 큰 금액으로 자동주문하지 않습니다. 주문 실행 플래그를 끈 dry-run, 모의투자 또는 아주 작은 금액으로 인증·종목·방향·수량·거래소/시장 구분을 검증하는 편이 안전합니다.

6. 운영 단계에서는 실패를 전제로 설계합니다

실전에서는 토큰 만료, API 호출 제한, 네트워크 오류, 미체결, 거래시간, 주문 거부, 서버 재시작이 발생합니다. 백테스트 코드보다 실제 운영 시스템이 더 복잡해지는 이유입니다.
