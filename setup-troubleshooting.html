Python · VS Code

Python'python'은(는) 내부 또는 외부 명령 … 이 아닙니다 · command not found: python · Microsoft Store가 열림

원인 · Python이 설치되지 않았거나, 설치는 됐지만 터미널이 Python 위치(PATH)를 모릅니다.

해결
  • Windows: 명령 프롬프트를 새로 열고 py -3 --version을 먼저 확인합니다. 버전이 나오면 python 대신 py로 실행해도 됩니다.
  • 설치 파일(B방식)로 설치했다면 다시 실행해 Modify에서 PATH 등록을 켜거나, 재설치하면서 Add python.exe to PATH를 체크합니다.
  • Microsoft Store만 열리면 Windows 설정의 앱 실행 별칭에서 python 항목을 확인합니다.
  • Mac은 python이 아니라 python3를 씁니다.

참고: 1단계 2번 · Python 공식 Windows 설치 안내

Python모듈 설치 실패: error: subprocess-exited-with-error · Preparing metadata (pyproject.toml) did not run successfully · Could not parse vswhere.exe output

원인 · 2026년 10월에 나온 Python 3.15용 설치 파일이 pandas 등 일부 모듈에 아직 없어서, pip가 직접 컴파일하려다 실패합니다.

해결
  1. Python 3.14를 설치합니다(Windows는 Add python.exe to PATH 체크). 3.15를 지우지 않아도 되지만, 헷갈리면 지워도 됩니다.
  2. 새 명령 프롬프트에서 py -3 --version으로 3.14가 잡히는지 확인합니다.
  3. GMA Runner를 쓴다면 Runner를 끄고 다시 실행한 뒤 게만아 기본 모듈 설치/복구를 누릅니다. 그래도 3.15로 보이면 Runner를 끈 상태에서 %LOCALAPPDATA%\GMA Runner 안의 runtime 폴더를 지우고 다시 실행합니다.
  4. Visual Studio Build Tools는 설치할 필요가 없습니다.

VS Code실행 버튼을 눌러도 반응이 없음 · 「파이썬 확장 로드 중」이 계속됨

원인 · 인터프리터(사용할 Python) 경로가 꼬였거나, VS Code·확장 버전이 PC 환경과 맞지 않습니다.

해결
  • VS Code를 완전히 껐다가 다시 켭니다.
  • 오른쪽(또는 왼쪽) 아래에 Python 버전이 보이는지 확인하고, 없으면 눌러서 Recommended Python을 고릅니다.
  • 실행 → 디버깅 없이 실행으로 실행합니다.
  • 그래도 안 되면 Python 확장을 다시 설치하거나, 확장 화면에서 버전을 바꾼 뒤 인터프리터를 다시 지정합니다. 오래된 Windows(예: Windows Server 2016)에서는 VS Code 예전 버전을 설치해 해결한 사례가 있습니다.

참고: 카페 637번 글 · 카페 965번 글

모듈 · 키 · 파일 위치

모듈ModuleNotFoundError: No module named '…'

원인 · 두 가지 경우가 있습니다. ① pandas·yfinance 같은 외부 모듈이 설치되지 않음 ② myUpbitNew·KIS_Common·line_alert 같은 게만아 공통모듈 파일이 같은 폴더에 없음.

해결
  • ①이면 pip install 모듈명(서버는 pip3 install 모듈명). 여러 Python이 깔린 PC는 python -m pip install 모듈명(Mac은 python3 -m pip install 모듈명)로 설치하세요. GMA Runner는 기본 모듈 설치/복구 버튼을 누릅니다.
  • 모듈 이름과 설치 이름이 다른 경우: yaml → pyyaml, bs4 → beautifulsoup4
  • ②이면 설치가 아니라 해당 파일을 봇과 같은 폴더(Workspace, 서버는 /var/autobot)에 넣습니다. 공통모듈은 구매 콘텐츠의 공통모듈 링크에서 받습니다.

참고: 모듈이 없다고 에러가 날 때

원인 · 최신 pandas와 pandas_datareader가 맞지 않습니다.

해결
pip uninstall -y pandas numpy
pip install --user pandas==2.3.3 numpy==1.26.4

환경에 따라 pip3를 씁니다. 카페 답변 기준 해결 방법이며, Python 버전을 3.14 이하로 맞추는 것도 함께 확인하세요.

키import ende_key · import my_key 파일이 없다고 나옴 · 키를 어디에 넣는지 헷갈림

원인 · 키를 암호화해서 쓰는 방식의 예시 줄입니다. 직접 키를 넣는 방식이면 필요 없습니다.

해결
  • 두 import 줄을 지우거나 앞에 #을 붙여 주석 처리하고, 안내된 자리에 키를 직접 넣습니다.
  • 코인 키 위치: 업비트 myUpbitNew.py, 빗썸 myBithumb.py, 코인원 myCoinone.py · 주식은 my증권사_StockInfo.yaml
  • AI에게 「알아서 고쳐 줘」라고 맡기면 엉뚱한 곳을 고쳐 더 헤맬 수 있습니다. 바꿀 위치를 정확히 알려 주세요.

참고: 패키지 세팅 안내 5) · 카페 656번 글

경로FileNotFoundError: [Errno 2] No such file or directory: '/var/autobot/my…_StockInfo.yaml' · './kakao_token.json'

원인 · 게만아 코드는 yaml·json을 명령을 실행한 위치(./) 기준으로 찾습니다. 서버용 경로를 내 PC에서 쓰거나, 파일을 다른 폴더에 두면 못 찾습니다.

해결
  • 내 PC(VS Code): 폴더 열기로 코드가 있는 폴더를 열고, yaml을 코드와 같은 폴더에 둡니다. 경로는 ./를 씁니다.
  • GMA Runner: 필요한 파일을 모두 Workspace에 넣습니다.
  • AWS 서버: .py와 공통모듈은 /var/autobot, yaml·json은 /home/ec2-user. 손으로 실행할 때도 cd 없이 홈 폴더에서 python3 /var/autobot/파일.py

경로어느 날부터 json 관련 오류가 남 (예: 업데이트 후 KR_Market_OpenCheck.json 오류)

원인 · 실행 중 만들어지는 json 파일이 잘못된 형식으로 저장된 경우입니다.

오류에 나온 json 파일을 지우고 다시 실행하면 새로 만들어집니다. 내 설정이 들어 있는 json이라면 지우기 전에 복사해 두세요.

GMA Runner

RunnerMac에서 「GMA_Runner_Mac.command을(를) 열지 않음」 경고

원인 · 인터넷에서 받은 .command 파일을 macOS가 확인하지 않은 파일로 막습니다.

해결
  • 먼저 같은 폴더의 GMA_Runner_Mac 앱을 실행합니다(권장).
  • .command를 써야 한다면 경고 창에서 완료 → 시스템 설정 → 개인정보 보호 및 보안 → 아래로 내려 그래도 열기 → 암호 입력
  • 앱만 응용 프로그램 폴더로 옮겼다면 폴더째 원래 자리에 두고 실행합니다.

Runner예약한 시간에 실행되지 않음 · 터미널 창을 닫았더니 멈춤

원인 · Runner 안내 창이 닫혔거나, PC가 절전·재부팅 상태였거나, 자동 실행이 꺼져 있습니다.

해결
  • 안내 창(검은 터미널 창)은 최소화만 하고 닫지 않습니다. 닫았다면 Launcher를 다시 실행합니다.
  • 재부팅 후에는 Launcher를 다시 실행해야 합니다. 전략이 도는 시간에는 절전을 꺼 둡니다.
  • 자동 실행 목록에서 켜짐 상태와 다음 실행 시각을 확인합니다. crontab 예시를 붙여 넣었다면 Cron 시간대(UTC)도 확인합니다.

증권사·거래소 API

API키움 「검증에 실패」 · 한국투자 Get Authentification token fail! · 토큰 발급 실패

원인 · yaml에 「여러분의 앱키」 같은 예시 문구가 그대로 남았거나, 키를 잘못 복사했거나(앞뒤 공백 포함), yaml이 코드가 찾는 위치에 없습니다.

해결

  2. 서버라면 고친 yaml을 다시 업로드했는지, /home/ec2-user에 있는지 확인합니다.
  3. 토큰 발급만 따로 시험하려면 아래 두 줄만 실행해 봅니다(한국투자 예시, 다른 증권사는 공통모듈 이름만 바꿉니다).
import KIS_Common as Common
Common.SetChangeMode("REAL")

AWS-bash: crontab: command not found

해결

참고: 3단계 2번 · 카페 144번 글

AWS직접 실행하면 되는데 crontab으로는 안 도는 것 같음

원인 · crontab 맨 위에 넣은 SHELL=·PATH= 줄, 파일 위치(./) 문제가 흔합니다. 실제로는 실행됐는데 매매 조건이 맞지 않아 주문·알림이 없었던 경우도 많습니다.

해결
  • 임의로 넣은 SHELL·PATH 줄을 지우고 MAILTO=""부터 시작합니다.
  • 명령은 절대경로로 씁니다: python3 /var/autobot/파일.py. yaml·json은 /home/ec2-user에 둡니다.
  • 봇 첫 부분에 line_alert.SendMessage("봇 실행 확인")을 넣어 실행 여부부터 가립니다. crontab 자체가 동작하지 않는 경우는 드뭅니다.
  • 서버 시간은 UTC(한국 -9시간)입니다. 시간을 잘못 적지 않았는지 확인합니다.

참고: 카페 307번 글 · 카페 723번 글 · 카페 752번 글

AWS서버 접속·업로드가 헷갈림 · yaml을 넣었는데도 오류 · 서버에서 알림이 안 옴

원인 · root로 접속했거나, 고친 파일을 저장·업로드하지 않았거나, 다른 폴더에 올린 경우가 많습니다. cat(파일 내용 보기)으로 실행하려는 실수도 있습니다.

해결
  • 사용자는 ec2-user로 접속합니다.
  • 순서: VS Code에서 고치고 저장 → FileZilla로 업로드 → 올린 폴더가 맞는지 확인
  • 실행은 python3 /var/autobot/파일.py입니다.
  • 내 PC에서 접속 화면이 떴다면 이미 서버에 연결된 것입니다. AWS 웹에서 하던 crontab 작업을 그 창에서 그대로 하면 됩니다.

참고: 3단계 4번 · 카페 542번 글 · 카페 647번 글

AWSFileZilla·SSH 접속이 안 됨 · 키 파일 오류

원인 · .pem 키 파일을 등록하지 않았거나, 서버 홈 폴더의 접속 설정 파일을 지워 접속 키가 손상됐을 수 있습니다.

해결
  • FileZilla 설정 → SFTP에 .pem이 등록되어 있는지, 사이트 관리자에서 프로토콜 SFTP·사용자 ec2-user인지 확인합니다.
  • Mac·리눅스 터미널에서 ssh로 접속할 때 키 권한 오류가 나면 chmod 400 키파일.pem으로 권한을 줄입니다.
  • 서버 홈 폴더의 숨김 파일을 지워 접속이 끊겼다면, 서버를 새로 만들고 탄력적 IP를 새 서버에 연결합니다.

참고: 카페 330번 글

AWS봇이 Killed라는 메시지와 함께 종료됨

원인 · 서버 메모리가 부족합니다. 알트코인 전략처럼 메모리를 많이 쓰는 코드는 작은 서버에서 멈출 수 있습니다.

해결

서버 메모리 확장 글대로 스왑 메모리를 늘립니다. GMA_AutobotServer로 만든 서버는 이미 되어 있습니다. 봇이 많다면 서버 안정화도 확인하세요.

AWSAmazon Linux 2 지원 종료 메일을 받음 · 서버를 옮기고 싶음

원인 · 예전 Amazon Linux 2 기반 서버는 2026년 6월 30일로 지원이 끝났습니다.

해결
  1. GMA_AutobotServer로 새 서버를 만듭니다.
  2. 파일과 crontab 내용을 옮깁니다.
  3. 기존 탄력적 IP를 새 서버에 연결합니다. 그러면 증권사·거래소에 등록한 IP를 그대로 쓸 수 있습니다.
  4. 문제없이 도는지 확인한 뒤 예전 서버를 종료합니다.

AWS서버를 그만 쓰고 싶음 · 비용이 계속 나옴

원인 · 서버를 중지만 했거나, 탄력적 IP를 해제하지 않았습니다. 탄력적 IP는 연결해 두어도, 서버가 없어도 비용이 나옵니다.

AWS 콘솔에서 인스턴스를 종료하고, 탄력적 IP 메뉴에서 해제합니다. 요금은 AWS 결제 대시보드에서 확인합니다.

  • line_alert.py에서 연동한 메신저 줄의 주석을 풀었는지, 봇에서 SendMessage를 부르는지 확인합니다.

자주 묻는 질문

모듈을 설치했는데도 ModuleNotFoundError가 나요.

여러 Python이 설치되어 있으면 다른 Python에 설치됐을 수 있습니다. python -m pip install 모듈명(Mac은 python3 -m pip install)으로 설치하세요. myUpbitNew·KIS_Common 같은 게만아 공통모듈은 설치가 아니라 같은 폴더에 파일을 넣어야 합니다.

pip 설치가 subprocess-exited-with-error로 실패해요.

대개 Python 3.15 때문입니다. Python 3.14를 설치한 뒤 다시 설치하세요. GMA Runner는 다시 실행한 뒤 기본 모듈 설치/복구를 누릅니다.

서버에서 FileNotFoundError가 나요.

게만아 코드는 yaml·json을 명령을 실행한 위치 기준으로 찾습니다. 서버에서는 .py와 공통모듈을 /var/autobot에, yaml·json을 /home/ec2-user에 두고, 홈 폴더에서 python3 /var/autobot/파일.py로 실행하세요.

crontab에 등록했는데 봇이 안 도는 것 같아요.

crontab 맨 위의 SHELL·PATH 줄을 지우고 MAILTO=""부터 시작하세요. 명령은 절대경로로 쓰고, 서버 시간이 UTC(한국 -9시간)인지 확인하세요. 봇 첫 부분에 실행 확인 메시지를 넣으면 실행 여부를 바로 알 수 있습니다.

토큰 발급 실패가 나요.

yaml에 예시 문구가 남아 있거나 키를 잘못 넣은 경우가 많습니다. 키를 다시 넣고 저장한 뒤, 서버라면 yaml을 다시 업로드하세요. 공통모듈을 불러오고 SetChangeMode("REAL")만 실행해 토큰 발급만 따로 시험할 수 있습니다.
