2단계 · 구매자 · 내 PC 자동 실행

GMA Runner로 내 PC에서 자동 실행하기

서버 없이 Windows·Mac PC에서 파일 준비 → 수동 실행 → 자동 실행 → 로그 확인을 한 화면에서 합니다. 슈퍼 이동평균·코인 더블 이동평균 New·게만아 패키지 구매자에게 함께 제공되는 실행 도구입니다.

끝나면 · 정한 시간(예: 매일 1회)에 전략 파일이 자동으로 실행되고, 실행 결과와 오류가 로그로 남습니다. Windows 작업 스케줄러나 Mac cron을 직접 설정할 필요가 없습니다.

전체 지도1단계 · 무료 Starter2단계 · GMA Runner3단계 · AWS 서버오류 해결

시작 전에

  • Python 3.14와 VS Code가 설치되어 있어야 합니다. → 1단계 2~3번 (Starter 실습은 선택)
  • GMA Runner는 따로 팔지 않고, 구매한 콘텐츠의 구글 드라이브에 GMA_RUNNER.zip으로 들어 있습니다.
  • 예약 시각에 PC가 켜져 있고 Runner가 실행 중이어야 합니다. 절전·재부팅 중에는 실행되지 않습니다.

  1. 압축 풀고 폴더 통째로 두기

    GMA_RUNNER.zip의 압축을 모두 풀고, GMA_RUNNER 폴더를 통째로 바탕화면·문서처럼 편한 곳에 둡니다.

    • Mac은 앱만 따로 응용 프로그램 폴더로 옮기지 마세요. 폴더째 두고 그 안의 앱을 실행합니다.
    • 휴지통에 넣은 폴더에서 실행하지 마세요.
    • 폴더 안에 왕초보 가이드 PDF가 함께 들어 있습니다.

    됐는지 확인 · 폴더 안에 GMA_Runner_Windows.bat, GMA_Runner_Mac(앱), Scheduler_Check.py, 왕초보 가이드 PDF가 보입니다.

  2. Runner 실행

    Windows

    GMA_Runner_Windows.bat(Windows 배치 파일)을 더블클릭합니다.

    Mac

    GMA_Runner_Mac 앱(R 아이콘)을 더블클릭합니다. 안 열리면 같은 폴더의 GMA_Runner_Mac.command를 실행합니다. 「열지 않음」 경고가 뜨면 완료를 누르고 시스템 설정 → 개인정보 보호 및 보안에서 아래로 내려 그래도 열기를 누른 뒤 암호를 입력합니다.

    처음 실행할 때는 실행환경을 준비하느라 시간이 조금 걸립니다(인터넷 연결 필요). Python이 없거나 지원 버전을 찾지 못하면 Launcher가 설치 순서를 안내합니다.

    됐는지 확인 · 브라우저에 GMA Runner 화면이 열립니다. 인터넷 사이트가 아니라 내 PC 안에서 열리는 관리 화면입니다.

    꼭 기억 · 함께 뜬 안내 창(검은 터미널 창)은 닫지 말고 최소화하세요. 닫으면 Runner가 꺼집니다. 브라우저는 닫아도 되고, 다시 열 때는 같은 Launcher를 더블클릭합니다.

    원본: GMA Runner V1 배포 글

  3. 처음 3분 실습

    새 Workspace면 처음 3분만 따라 해보세요 화면이 자동으로 열립니다. 실습 파일 Scheduler_Check.py는 주문·계좌·API·외부 모듈을 전혀 쓰지 않는 안전한 연습 파일입니다.

    1. 실행 환경 확인
    2. 샘플 파일 준비하기 → 샘플 지금 실행
    3. 1분 자동 실행 만들어보기 → 기본값(1분마다) 그대로 자동 실행 저장

    됐는지 확인 · 샘플을 실행하면 텍스트 창이 뜨고, 1분 자동 실행을 저장하면 1분마다 다시 뜹니다. 확인했으면 샘플 자동 실행은 꺼 두세요.

  4. 기본 모듈 한 번에 설치

    오른쪽 위 환경 설정에서 Python 실행환경이 정상인지 보고, 게만아 기본 모듈 설치/복구를 누른 뒤 확인합니다. pandas, requests, yfinance, ccxt 등 게만아 코드에 쓰는 모듈 19개를 차례로 설치합니다. 명령어를 입력할 필요가 없습니다.

    됐는지 확인 · 모듈 목록이 모두 설치됨(19/19 준비됨)으로 바뀌고 최근 설치가 SUCCESS로 나옵니다. 미설치 항목이 남으면 버튼을 한 번 더 누릅니다.

    막히면 · 설치가 실패하면 대개 Python 3.15 때문입니다. → 오류 해결: 모듈 설치가 실패함

  5. 전략 파일 고치고 Workspace에 넣기

    1. 받은 전략 폴더를 VS Code로 열고, 코드 맨 위의 관련 가이드(필독) 포스팅부터 읽습니다. 필요한 파일과 설정값이 적혀 있습니다.
    2. 설정값을 내 것으로 바꿉니다. 포트폴리오, 투자 비중(InvestRate 등), API 키(아래 6번)입니다.
    3. Runner 상단 전략 파일 메뉴에서 Workspace 폴더 열기를 눌러 열린 폴더에 파일을 복사하거나, + 파일 추가로 넣습니다.
    • 봇 파일, 공통모듈, 설정 yaml, json을 모두 같은 Workspace에 넣어야 실행됩니다. Runner는 빠진 파일을 알아서 찾아 주지 않습니다.
    • 코드를 고칠 때는 원본을 VS Code에서 고친 뒤 다시 넣어 덮어씁니다. 실행 중인 파일이나 쓰고 있는 json을 직접 덮어쓰면 오류가 날 수 있습니다.

    됐는지 확인 · 전략 파일 목록에 넣은 파일이 보이고, 파일마다 관련 필수 포스팅 링크가 자동으로 붙습니다.

  6. API 키 넣고 IP 등록

    구분키를 넣는 곳안내
    주식증권사별 my증권사_StockInfo.yaml1단계 6번과 같습니다. 슈퍼 이동평균 기본 코드는 DB증권 API 기준입니다.
    업비트myUpbitNew.py의 POCKET_KEYS업비트 포켓 안내
    빗썸myBithumb.py의 API_KEY·SECRET_KEY빗썸 안내
    코인원myCoinone.py의 PORTFOLIO_KEYS코인원 안내
    • 거래소·증권사가 IP 등록을 요구하면 내 PC의 공인 IP를 등록합니다. 가정용 IP도 가끔 바뀌므로, 갑자기 API 연결이 안 되면 현재 IP부터 확인하세요.
    • 코인 거래소 API에는 출금 권한을 주지 않습니다.
    • 봇 코드에 import ende_key, import my_key 같은 줄이 있다면 암호화 방식 예시입니다. 직접 키를 넣는 방식이면 그 줄을 지우거나 주석 처리하세요. → 오류 해결

  7. 수동 실행으로 먼저 확인

    백테스트(_Test.py)나 데이터를 만드는 파일부터 수동 실행을 눌러 봅니다. RUNNING(실행 중)이 끝나면 SUCCESS 또는 FAILED가 나옵니다.

    • FAILED면 로그 보기의 오류 출력을 확인합니다. 그 내용을 오류 해결 페이지에서 찾거나 AI·카페에 물어보세요(일반 출력도 함께).
    • 예: No module named 'myUpbitNew'는 설치할 모듈이 아니라 게만아 공통모듈 파일이 Workspace에 없다는 뜻입니다. 해당 파일을 넣으면 됩니다.

    됐는지 확인 · SUCCESS가 나오고 로그의 일반 출력에 결과가 보입니다. 백테스트는 그래프 창이 뜹니다.

  8. 자동 실행 등록

    1. 상단 자동 실행 → 새 자동 실행 만들기
    2. 실행할 파일을 고릅니다(Workspace에 있는 파일만 보입니다). 이름은 자동으로 채워지고 바꿔도 됩니다.
    3. 스케줄 종류를 고릅니다: N분마다 · 매일 · 매주 · 특정 요일과 시간대 · 매월 · Crontab 한 줄 가져오기
    4. 저장 후 자동 실행 사용이 체크되어 있는지 보고, 아래에 나오는 다음 실행 3개가 의도와 맞는지 확인한 뒤 자동 실행 저장을 누릅니다.

    코드 맨 위에 crontab 예시가 적힌 파일은 실행 시간이 자동으로 채워집니다. 게만아의 crontab 예시는 AWS 서버(UTC) 기준이라, 직접 붙여 넣을 때는 Cron 시간대를 UTC · 기존 AWS 추천 예시로 두고 다음 실행 시각(한국 시간)을 확인하세요.

    됐는지 확인 · 자동 실행 목록에 켜짐 상태와 다음 실행 시각이 보입니다. 첫 예약 시각이 지나면 로그에서 실행 결과를 확인하세요.

  9. 실전 전에 꼭 확인

    • 투자 비중 — InvestRate 같은 값은 0~1입니다. 0.3이면 계좌의 30%를 이 전략에 씁니다. 처음에는 낮게 시작하세요. 1.0 같은 올인은 시장가 주문의 증거금 때문에 주문이 실패할 수 있어 권장하지 않습니다.
    • 주문 실행 여부 — ENABLE_ORDER_EXECUTION이 있는 봇은 기본값이 False이고, True로 바꿔야 실제 주문이 나갑니다.
    • 결과 확인 — 첫 자동 실행 뒤에는 증권사·거래소 앱에서 주문과 잔고를 직접 확인합니다.

예시: 코인 더블 이동평균 New를 Runner로 돌리는 흐름

코인 더블 이동평균 New 세팅 가이드의 흐름을 줄이면 이렇습니다. 다른 전략도 순서는 비슷합니다.

  1. 사용하는 거래소의 API 키를 공통모듈 파일에 넣습니다(위 6번).
  2. MakeFindMa_Coin.py를 열어 거래소별 포트폴리오를 정합니다. 쓰지 않는 거래소 목록은 비워 둡니다.
  3. 모든 파일을 Workspace 한 곳에 넣고, 백테스트 파일을 수동 실행해 결과를 봅니다.
  4. 자동 실행을 두 개 등록합니다. MakeFindMa_Coin.py는 매월 1회, 거래소별 봇은 매일 1회입니다.
  5. MakeFindMa_Coin.py는 처음 한 번 지금 실행을 눌러 봇이 쓸 json 파일을 미리 만들어 둡니다.

슈퍼 이동평균은 기본 코드가 DB증권 API 기준이며 하루 한 번 정해진 시점에 실행하는 구조입니다. 구매 시 제공되는 세팅 가이드대로 같은 방식으로 Runner에 등록하면 됩니다.

PC로 운용할 때 알아둘 것

  • PC가 꺼지거나 절전 상태면 예약 실행이 시작되지 않습니다. 전략이 도는 시간에는 절전을 꺼 두세요.
  • 재부팅이나 업데이트 뒤에는 Launcher를 다시 실행해야 합니다.
  • 집 인터넷의 공인 IP가 바뀌면 IP를 등록한 API 연결이 끊길 수 있습니다.
  • 24시간 완전 자동화나 고정 IP가 중요해지면 3단계 · AWS 서버로 옮기면 됩니다. 계속 켜둘 PC가 있다면 Runner만 계속 써도 됩니다.

자주 묻는 질문

브라우저를 닫으면 자동 실행도 멈추나요?

브라우저만 닫는 것은 괜찮습니다. 다만 Runner 안내 창(터미널 창)이 살아 있고 PC가 깨어 있어야 예약 실행이 계속됩니다. 재부팅 후에는 Launcher를 다시 실행하세요.

Runner 안에서 코드를 고칠 수 있나요?

코드 수정은 VS Code 같은 편집기에서 하고, 고친 파일을 다시 Workspace에 넣어 덮어씁니다. Workspace 파일은 원본과 다른 위치의 복사본이라 헷갈리지 않도록 기능을 나눴습니다.

기존 AWS crontab 줄을 그대로 쓸 수 있나요?

네. 스케줄 종류에서 'Crontab 한 줄 가져오기'를 고르고 붙여 넣으면 됩니다. 게만아 예시는 UTC 기준이니 Cron 시간대를 UTC로 두고 다음 실행 시각을 확인하세요.

Runner를 쓰다가 AWS로 꼭 옮겨야 하나요?

아닙니다. 전략이 도는 시간 동안 PC를 확실히 켜둘 수 있다면 Runner만으로도 충분합니다. 24시간 안정성이 중요해질 때 AWS로 옮기면 됩니다.
