바이낸스 API 파이썬 자동매매 가이드

바이낸스 자동매매는 파이썬 ccxt 모듈을 활용하며, 현물 API와 선물 API가 전혀 달라 따로 구현합니다. 선물은 헤지 모드(양방향)를 기본으로 쓰고, 돌파 진입이나 트레일링 스탑 같은 여러 주문 유형을 활용할 수 있습니다. 다만 코인 선물은 레버리지로 손실이 커질 수 있어 게만아는 초보자가 선물로 시작하는 것에 반대합니다.

파이썬 자동매매 연동 순서

  1. 바이낸스 계정을 준비하고, 공식 안내에 따라 API 키를 발급합니다(권한과 IP 제한은 공식 안내 확인).
  2. 현물을 쓴다면 현물 지갑에 USDT를 두고, 선물을 쓴다면 선물 지갑을 준비합니다. 필요하면 [Transfer]로 지갑 사이에 옮깁니다.
  3. 선물이라면 포지션 모드를 헤지 모드(양방향)로 맞춥니다.
  4. 파이썬에 ccxt를 설치하고 API 키를 공통 코드의 설정에 넣습니다.
  5. 조회부터 테스트(잔고 → 현재가)한 뒤, 주문은 가장 작은 금액·낮은 레버리지로 확인합니다.
  6. 스탑·트레일링 스탑 주문을 쓴다면 스탑 트레이더 시스템 파일이 서버에서 1분마다 실행되도록 crontab에 등록합니다.

게만아 공통모듈로 쓰면

바이낸스 봇은 ccxt를 기반으로 만들어 현물·선물 주문과 포지션 조회를 파이썬으로 다룹니다. 선물 코드는 헤지 모드(LONG/SHORT)를 전제로 하며, 현물 코드의 Buy/Sell 대신 롱·숏에 맞춰 Open/Close로 함수명을 구분합니다.

스탑 주문, 스탑로스 주문, 활성화 가격이 있는 트레일링 스탑 주문을 한 시스템으로 다루는 스탑 트레이더는 이전에 현물 거래소용으로 만든 스탑 트레이더 함수들과 같은 아이디어를 선물에 맞게 옮긴 것입니다. 활성화 가격이 없는 일반 스탑 주문과 즉시 발동하는 트레일링 스탑은 기존 ccxt 주문으로도 충분히 넣을 수 있습니다.

실전에서 주의할 점

  • 코인 선물은 위험합니다. 레버리지 때문에 원금 이상의 손실이 날 수 있으며, 게만아는 초보자가 선물로 시작하는 것에 반대합니다. 선물을 한다면 소액·낮은 레버리지로 시작하세요.
  • 현물과 선물은 API가 다릅니다. 현물 코드를 선물에 그대로 쓸 수 없습니다.
  • 포지션 모드를 확인하세요. 게만아 선물 봇은 헤지 모드를 전제로 하므로, 원웨이 모드면 주문이 의도와 다르게 동작할 수 있습니다.
  • 바이낸스 API는 바뀔 수 있습니다. 2025-12-09에 조건부 주문이 Algo 주문 API로 이동해 기존 엔드포인트가 이런 주문을 거절(-4120)하게 됐고, 게만아도 거의 모든 코드를 수정해야 했습니다. 코드를 직접 짠다면 변경 로그를 확인하세요.
  • 스탑 트레이더는 서버에서 계속 실행되어야 합니다. 시스템 파일이 멈추면 스탑·트레일링 기능이 동작하지 않습니다.
  • 트레일링 스탑이 들어가는 전략은 캔들 백테스트로 재현하기 어렵습니다. 언제 청산될지 캔들만으로 알 수 없기 때문입니다. 실제 운용 결과와 다를 수 있습니다.
  • 분봉 단위 매매는 수수료 영향이 큽니다. 주기가 짧아질수록 매매 횟수와 수수료가 늘어납니다.
  • 응답이 불안정할 때의 처리는 API 불안정 대응 가이드를 참고하세요.

자주 묻는 질문

바이낸스 파이썬 자동매매는 어떻게 하나요?

파이썬 ccxt 모듈로 바이낸스 현물·선물 주문과 포지션 조회를 다룹니다. 티커는 BTC/USDT 형식이고, 현물과 선물은 API가 달라 따로 구현해야 합니다. 먼저 조회부터 테스트하고 주문은 소액으로 확인하세요.

바이낸스 현물 API와 선물 API는 같은가요?

아니요. 현물 API는 선물 API와 전혀 달라서 같은 방식으로 호출할 수 없습니다. 게만아는 현물용과 선물용 코드를 따로 둡니다.

바이낸스 선물에서 헤지 모드란 무엇인가요?

롱(LONG)과 숏(SHORT) 포지션을 동시에 가질 수 있는 양방향 모드입니다. 게만아 선물 봇은 기본적으로 헤지 모드를 사용하며, 원웨이(단방향) 모드라면 헤지 모드로 바꿔야 합니다.

바이낸스에서 돌파 가격에 미리 주문을 걸 수 있나요?

가능합니다. 현재가보다 위에 일반 롱 주문을 넣으면 바로 체결되기 때문에, 돌파 진입은 스탑 주문(STOP_MARKET)으로 넣습니다. 다만 2025-12-09부터 이런 조건부 주문은 새 Algo 주문 API(POST /fapi/v1/algoOrder)로 옮겨졌고, 기존 주문 엔드포인트는 오류(-4120)를 돌려줍니다.

바이낸스 트레일링 스탑 주문이 오류(-4120)로 거절됩니다.

2025-12-09부터 바이낸스가 조건부 주문(STOP_MARKET·TRAILING_STOP_MARKET 등)을 새 Algo 주문 API로 옮겨, 기존 주문 엔드포인트로 보내면 -4120 오류가 납니다. 게만아는 2025-12-16 포스팅 시점에 ccxt로 활성화 가격이 있는 트레일링 스탑을 넣을 수 없는 한계를 확인해 서버 로직의 스탑 트레이더 시스템(패키지 79번)을 만들었습니다. 바이낸스 공식 문서의 Algo 주문에는 활성화 가격(activatePrice)이 명시돼 있으니, 현재 가능 여부는 공식 문서와 사용하는 ccxt 버전을 확인하세요.

바이낸스 선물로 자동매매를 시작해도 되나요?

게만아는 초보자가 코인 선물로 투자를 시작하는 것에 반대합니다. 레버리지로 손실이 커질 수 있기 때문입니다. 이미 선물 자동매매를 하고 있고 위험을 감수할 수 있는 경우에도 소액·낮은 레버리지로 시작하는 것이 안전합니다.

근거와 확인 시점

이 페이지는 게만아의 바이낸스 선물 스탑 주문 시스템 포스팅(패키지 79번, 2025-12-16 게시), 바이낸스 ccxt 주문 포스팅(2023-11-15), 바이낸스 현물·선물 전략 포스팅(2024-05-17)을 바이낸스 개발자 문서의 변경 로그(2025-12-09 조건부 주문 Algo 이전)와 대조해 정리한 것입니다. 바이낸스의 키 발급 절차와 IP 제한은 다루지 않았으며 공식 안내를 확인해야 합니다. 거래소의 API 사양과 정책, 가입·발급 조건은 바뀔 수 있으므로 키 발급과 실제 주문 전에 공식 문서의 최신 내용을 확인하세요.
