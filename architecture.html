증권사·거래소 API를 공통 구조로 묶는 방법

주식 증권사와 코인 거래소는 인증과 주문 규격이 서로 다르지만, 전략이 필요로 하는 기능은 상당 부분 비슷합니다. 전략 로직과 시장 연결 코드를 분리하면 같은 시스템을 확장하기 쉬워집니다.

개념 구조

Strategy / Backtest
        ↓
Common Interface
  ├─ GetBalance()
  ├─ GetPositions()
  ├─ GetCurrentPrice()
  ├─ Buy()
  └─ Sell()
        ↓
Adapter Layer
  ├─ Stock Broker Adapter
  │    ├─ KIS
  │    ├─ Kiwoom
  │    └─ ...
  └─ Crypto Exchange Adapter
       ├─ Upbit
       ├─ Bithumb
       ├─ Coinone
       └─ Binance
        ↓
Official API

공통화의 장점

  • 전략 코드를 시장 연결부와 분리할 수 있습니다.
  • 새 증권사·거래소를 추가할 때 기존 전략 수정량이 줄어듭니다.
  • 인증·헤더·symbol 형식·응답 파싱 차이를 Adapter 안으로 숨길 수 있습니다.
  • 조회 기능과 주문 기능을 분리해 테스트하기 쉽습니다.

억지로 공통화하지 말아야 할 기능

주식의 KRX/NXT/SOR, 미국주식 거래소 구분, 코인 선물의 롱·숏·레버리지·포지션 모드처럼 시장 고유의 개념은 별도 계층으로 남기는 편이 안전합니다.

인증정보는 코드와 분리

BROKER_APP_KEY=...
BROKER_APP_SECRET=...
EXCHANGE_API_KEY=...
EXCHANGE_SECRET=...

실제 키는 공개 GitHub 저장소에 올리지 않습니다.
