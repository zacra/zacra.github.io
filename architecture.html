주식과 코인은 API 구조를 다르게 구현합니다

게만아의 자동매매 코드는 주식과 코인 모두 “전략과 API 연결을 분리한다”는 원칙은 같지만, 실제 구현 방식은 같지 않습니다. 주식은 멀티브로커 전환 구조, 코인은 거래소별 별도 공통모듈 구조를 사용합니다.

주식: 같은 전략 파일에서 증권사 Broker를 전환

국내주식은 전략이 필요로 하는 잔고, 보유종목, 현재가, 주문 기능을 공통화하고, 사용할 증권사 Broker를 선택하는 방식으로 확장합니다.

같은 주식 전략 파일
        ↓
사용할 Broker 선택
        ↓
KIS / LS / 키움 / 토스 / KB / NH / DB
        ↓
각 증권사 Open API

그래서 동일한 투자전략을 여러 증권사에서 운용할 때 전략 전체를 다시 작성하는 부담을 줄일 수 있습니다.

코인: 업비트·빗썸·코인원·바이낸스를 각각 별도 구현

코인은 현재 주식처럼 한 파일에서 Exchange Adapter 하나만 바꾸는 구조가 아닙니다. 업비트, 빗썸, 코인원, 바이낸스 각각의 API 특성에 맞춘 공통모듈과 연결 코드를 따로 둡니다.

업비트용 전략/봇  → 거래소별 공통모듈 → 업비트 API
빗썸용 전략/봇    → myBithumb       → 빗썸 API
코인원용 전략/봇  → myCoinone       → 코인원 API
바이낸스용 전략/봇→ 거래소별 공통모듈 → 바이낸스 API

myBithumb, myCoinone처럼 거래소별 공통모듈이 독립되어 있고, 해당 거래소용 코드가 그 모듈을 사용합니다.

왜 코인을 억지로 하나로 합치지 않았나?

구분주식코인
지원 구조한 전략 파일에서 Broker 전환 가능거래소별 별도 구현
지원 대상한국투자·LS·키움·토스·KB·NH·DB업비트·빗썸·코인원·바이낸스
공통화증권사별 API 차이를 공통 인터페이스로 흡수거래소별 공통모듈을 각각 유지
이유주식 주문·계좌 기능의 공통분모가 큼인증·symbol·최소주문·정밀도·현물/선물 규칙 차이가 큼

중요한 것은 ‘무조건 하나로 합치기’가 아닙니다

좋은 아키텍처의 목적은 파일 개수를 줄이는 것이 아니라 전략의 의도와 API 차이를 안전하게 관리하는 것입니다. 공통화했을 때 단순해지는 영역은 공통화하고, 시장별 차이가 큰 부분은 분리하는 편이 오류를 줄이고 유지보수를 쉽게 만들 수 있습니다.

철학과 구조는 연결됩니다

게만아가 자동매매를 사용하는 이유도 같습니다. 더 복잡한 코드를 만드는 것이 목적이 아니라, 백테스트로 검증한 기준을 시장마다 빠뜨리지 않고 반복하기 위해 필요한 만큼만 시스템화합니다.
