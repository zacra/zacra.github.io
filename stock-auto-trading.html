파이썬 주식·ETF 자동매매 구조

주식·ETF 자동매매는 증권사 Open API를 통해 계좌와 시장을 연결하고, 전략이 계산한 목표상태와 실제 계좌상태의 차이를 주문으로 보정합니다. 게만아 코드의 핵심 특징 중 하나는 전략 로직과 증권사 API를 분리해 같은 전략을 여러 증권사·시장·계좌에서 재사용하기 쉽게 만든 것입니다.

증권사가 바뀌어도 전략 로직은 그대로

공통 인터페이스로 작성된 주식 봇에서는 아래 설정을 바꿔 Common과 API Helper를 동적으로 불러옵니다.

Broker = "KIS"       # KIS / DBI / LS / KIW / TOSS / KB / NH
Market = "KR"        # KR / US
accountMode = "REAL" # REAL / REAL2 / VIRTUAL 등

Common = importlib.import_module(f"{Broker}_Common")
Helper = importlib.import_module(f"{Broker}_API_Helper_{Market}")
Common.SetChangeMode(accountMode)

이후 전략에서는 Helper.GetBalance(), Helper.GetMyStockList(), Helper.GetCurrentPrice(), Helper.MakeBuyMarketOrder()처럼 공통된 호출 형식을 사용합니다. 즉 증권사별 인증·응답·주문 차이를 공통모듈이 흡수하고, 전략은 투자 규칙에 집중합니다.

모든 전략·모든 증권사·모든 계좌 조합이 동일 기능을 지원한다는 의미는 아닙니다. 시장·계좌·주문 유형은 각 증권사의 공식 API 지원 범위와 해당 공통모듈 구현 범위를 확인해야 합니다.

현재 다루는 증권사

현재 한국투자증권, LS증권, 키움증권, 토스증권, KB증권, NH투자증권, DB증권을 다룹니다. 지원사가 추가되어도 메뉴 이름은 숫자에 묶이지 않도록 멀티 증권사 API로 운영합니다.

전략 코드와 증권사 코드를 분리합니다

전략이 증권사의 원본 응답형식을 직접 알게 만들기보다, 각 증권사 Adapter/Common·Helper가 잔고·현재가·보유종목·주문을 공통 형태로 변환하도록 설계하면 동일 전략을 여러 환경으로 옮기기 쉬워집니다.

새 증권사를 추가할 때도 전략 파일 전체를 다시 작성하는 대신, 기존 공통 함수 규격을 만족하는 모듈을 추가하는 방향으로 확장할 수 있습니다.

공통모듈은 필요한 기능을 공통화한 실전용 레이어입니다

게만아의 증권사 공통모듈은 각 증권사 API 전체를 똑같이 복제하는 것이 목적이 아닙니다. 실제 전략에서 반복해서 사용하는 인증, 잔고, 보유종목, 시세, 주문 등의 기능을 공통 형태로 만들어 전략 코드가 증권사별 차이를 덜 신경 쓰도록 하는 구조입니다.

Starter는 이 구조의 입문용 최소 범위이며, 정식 콘텐츠에는 패키지와 슈퍼 이동평균 전략을 실제로 운용하는 데 필요한 핵심 API 기능이 이미 구현되어 있습니다. 일반적인 사용이라면 증권사 공식 문서를 보고 함수를 새로 만들 필요는 없습니다. 개인적으로 새로운 API 기능이 필요할 때만 공식 문서를 기준으로 추가 확장하면 됩니다.

또한 AI 확장은 공통모듈에만 한정되지 않습니다. 전략·백테스트·자동매매 봇·보조시스템까지 기존 코드를 바탕으로 수정·확장할 수 있습니다.
