3단계 · 24시간 · 서버

AWS 서버로 24시간 자동 실행하기

PC를 꺼도 정해진 시간에 봇이 돌게 하려면 AWS 같은 개인 클라우드 서버를 씁니다. 게만아가 미리 만들어 둔 서버 이미지 GMA_AutobotServer로 서버를 만들면 폴더·crontab·기본 모듈 준비가 끝난 상태에서 시작합니다.

끝나면 · 서버에 올린 파이썬 파일이 crontab에 정한 주기마다 실행되고, 실행할 때마다 내 메신저로 알림이 옵니다. 서버와의 접속 창을 닫아도, 내 PC를 꺼도 서버의 봇은 계속 돕니다.

전체 지도1단계 · 무료 Starter2단계 · GMA Runner3단계 · AWS 서버오류 해결

시작 전에

  • 내 PC에 Python·VS Code가 있으면 코드를 고치기 편합니다. → 1단계 2~3번
  • AWS 가입에 결제 카드가 필요합니다. 예전의 1년 무료(프리 티어)는 크레딧 방식으로 바뀌었고, 고정 IP(탄력적 IP)에는 서버에 연결해 두어도 소액 비용이 붙습니다. 요금과 혜택은 자주 바뀌니 AWS 공식 요금 안내에서 확인하세요.
  • 영상으로 먼저 보고 싶다면 더 쉬워진 세팅 글에 공개된 세팅 강의 3개(서버 세팅 · 스케줄러 · 메시지 보내기)를 보세요.

  1. AWS 계정 만들기

    1. AWS 가입 페이지에서 이메일과 계정 이름을 넣고, 이메일로 온 인증 코드를 입력합니다.
    2. 루트 사용자 암호를 정합니다.
    3. 연락처를 입력합니다. 한글로 써도 되지만 시·도 또는 리전 칸은 영문으로 씁니다.
    4. 결제 카드를 등록합니다. 확인용으로 소액이 결제될 수 있습니다.
    5. 전화번호 인증(SMS)을 하고, 지원 플랜은 기본 지원 - 무료를 고릅니다.

    로그인할 때는 루트 사용자 이메일을 사용하여 로그인을 고릅니다. 콘솔 오른쪽 위 설정 아이콘에서 언어를 한국어로 바꾸면 편합니다.

    됐는지 확인 · AWS Management Console(관리 화면)에 들어가집니다.

    원본: 더 쉬워진 세팅 2)

  2. EC2 서버 만들기 (GMA_AutobotServer)

    1. 콘솔 오른쪽 위 리전을 아시아 태평양(서울)로 바꿉니다. 처음에는 미국 버지니아 등으로 되어 있을 수 있습니다.
    2. 검색창에서 EC2로 들어가 인스턴스 시작을 누릅니다. AWS에서는 서버를 인스턴스라고 부릅니다.
    3. 이름은 편하게 짓고, 애플리케이션 및 OS 이미지에서 GMA_Autobot을 검색합니다. 바로 안 나오면 커뮤니티 AMI 탭을 누르고 GMA_AutobotServer를 선택합니다.
    4. 인스턴스 유형은 micro 크기로 시작해도 됩니다. 새로 만든다면 t3 계열을 권장합니다(서버 안정화 참고). 무료 혜택 라벨이 붙은 유형이 있다면 그것을 고르세요.
    5. 키 페어에서 새 키 페어 생성을 누르고 이름을 정합니다. 내려받은 .pem 파일은 서버 접속 열쇠입니다. 잃어버리지 말고 남에게 주지 마세요.
    6. 나머지는 그대로 두고 오른쪽의 인스턴스 시작을 누릅니다.

    GMA_AutobotServer에는 /var/autobot 폴더, crontab, pip, 기본 모듈, 메모리 확장이 미리 되어 있습니다. AWS 쪽 이미지가 바뀌어 새로 만들게 되더라도 같은 이름으로 검색되도록 관리합니다.

    됐는지 확인 · 인스턴스 상태가 실행 중으로 바뀝니다. 인스턴스를 선택하고 연결 → EC2 인스턴스 연결 탭에서 사용자 이름을 ec2-user로 바꿔 연결한 뒤, crontab -l과 cd /var/autobot을 입력해 오류 없이 실행되면 성공입니다.

    원본: 더 쉬워진 세팅 3)

  3. 고정 IP(탄력적 IP) 연결

    1. EC2 왼쪽 메뉴의 탄력적 IP → 탄력적 IP 주소 할당 → 아무것도 바꾸지 않고 할당
    2. 작업 → 탄력적 IP 주소 연결 → 방금 만든 인스턴스를 고르고 연결

    탄력적 IP가 없으면 서버를 다시 시작할 때 주소가 바뀝니다. 거래소·증권사 API 키를 발급할 때 넣는 허용 IP가 바로 이 주소입니다. 내 PC에서도 테스트하려면 내 PC 공인 IP도 함께 등록하세요.

    됐는지 확인 · 인스턴스 세부 정보에 탄력적 IP 주소가 보입니다.

    더 편하게: 내 PC에서 직접 AWS 서버에 접속하는 방법 · 보안을 위해 SSH 접속 제한하기

  4. FileZilla로 파일 올리기

    1. FileZilla(FTP 프로그램)를 설치하고 실행합니다.
    2. 설정(Mac은 FileZilla → 설정, Windows는 편집 → 설정)의 SFTP에서 키 파일 추가로 아까 받은 .pem을 등록합니다.
    3. 파일 → 사이트 관리자 → New site에서 프로토콜 SFTP, 사용자 ec2-user, 호스트에는 AWS 인스턴스 연결 → SSH 클라이언트 탭에 나오는 퍼블릭 DNS 주소(…amazonaws.com)를 넣고 연결합니다.
    4. 처음 연결할 때 뜨는 창에서 캐시에 등록을 고르고 확인합니다.

    왼쪽이 내 PC, 오른쪽이 서버입니다. 오른쪽 경로 칸에 /var/autobot을 입력해 이동한 뒤, 연습용 test.py(내용: print("My First Bot!!!"))를 끌어다 놓습니다.

    됐는지 확인 · 서버 접속 창에서 python3 /var/autobot/test.py를 입력하면 My First Bot!!!이 출력됩니다.

    막히면 · 접속이 안 되거나 root로 접속했다면 → 오류 해결: 서버 접속·업로드

  5. 파일 위치 규칙 (가장 많이 헷갈리는 부분)

    게만아 코드는 설정 yaml과 json 파일을 ./, 즉 명령을 실행한 위치를 기준으로 찾고 저장합니다. 서버에서 crontab은 홈 폴더(/home/ec2-user)에서 명령을 실행하므로 아래처럼 나눠 둡니다.

    파일서버에서 두는 곳
    봇·백테스트 파이썬 파일, 공통모듈(.py)/var/autobot
    증권사 설정 my증권사_StockInfo.yaml, 토큰·상태 json/home/ec2-user (FileZilla로 접속하면 처음 보이는 폴더)
    • 손으로 실행할 때도 cd로 옮겨 가지 말고 홈 폴더에서 python3 /var/autobot/파일.py처럼 실행합니다. 다른 폴더에서 실행하면 다른 위치의 json을 읽게 됩니다.
    • 내 PC(VS Code)나 GMA Runner에서는 모든 파일을 한 폴더(또는 Workspace)에 두면 됩니다.

    카페에 가장 자주 올라온 질문입니다: 카페 449번 글 · 카페 752번 글 · 카페 806번 글

  6. 모듈 최신화

    GMA_AutobotServer에는 기본 모듈이 이미 설치되어 있습니다. 바뀐 거래소 API에 맞추려고 아래를 서버에서 한 번 실행해 두세요.

    pip3 install --upgrade ccxt
pip3 install requests finance-datareader pykrx bs4 plotly pandas_datareader yfinance pyupbit ccxt pyyaml pytz tendo

    나중에 ModuleNotFoundError: No module named '모듈명'이 나오면 pip3 install 모듈명으로 설치합니다. 단, myUpbitNew나 KIS_Common 같은 게만아 공통모듈은 설치하는 것이 아니라 파일을 서버에 올려야 합니다.

  7. 나에게 메시지 보내기

    게만아 봇은 실행 결과를 메신저로 보내 줍니다. 메시지 보내기 글을 보고 텔레그램·슬랙·디스코드·카카오톡 중 하나를 연동하세요. 웹훅 주소만 넣으면 되는 디스코드가 가장 쉽습니다.

    봇들은 line_alert.py의 SendMessage로 메시지를 보냅니다. 연동한 메신저 줄의 주석(#)을 풀면 됩니다.

    # line_alert.py — 디스코드를 연동했다면
import discord_alert

def SendMessage(msg):
    print(msg)
    discord_alert.SendMessage(msg)

    알림 파일들을 /var/autobot에 올리고, test.py를 아래처럼 고쳐 다시 올립니다.

    import line_alert

print("My First Bot!!!")
line_alert.SendMessage("My First Bot!!!")

    됐는지 확인 · python3 /var/autobot/test.py를 실행하자마자 내 메신저에 메시지가 옵니다.

    막히면 · 카카오 KOE101이나 메시지가 안 오는 문제는 → 오류 해결: 메시지 알림

  8. crontab에 등록하기

    crontab은 정해진 시간마다 명령을 실행하는 서버의 스케줄러입니다. 게만아 봇은 한 번 돌고 끝나는 구조라, crontab이 주기마다 다시 실행해 줍니다.

    1. crontab -e를 입력해 편집 화면을 엽니다.
    2. 키보드 i를 누르면 아래에 -- INSERT --가 보입니다.
    3. 맨 위 MAILTO="" 아래에 */5 * * * * python3 /var/autobot/test.py를 입력합니다(5분마다 실행).
    4. ESC를 누르고 :wq를 입력한 뒤 Enter를 누르면 installing new crontab이 나옵니다.
    5. crontab -l로 등록된 내용을 확인합니다.

    서버 시간은 UTC · AWS 서버 시간은 한국보다 9시간 늦습니다. 한국 시간 오전 9시에 돌리려면 0시로 적습니다(0 0 * * *). 게만아 코드와 패키지 콘텐츠 가이드의 crontab 예시는 이 서버 시간 기준입니다.

    됐는지 확인 · crontab 실행은 백그라운드라 접속 화면에는 아무것도 안 보입니다. 5분마다 메신저 알림이 오면 성공입니다. 확인했으면 test 줄은 지우거나 앞에 #을 붙여 꺼 두세요.

    • crontab 맨 위에 SHELL=, PATH= 같은 줄을 임의로 넣지 마세요. MAILTO=""부터 시작하면 됩니다.
    • 봇을 잠깐 멈추려면 crontab에서 그 줄 맨 앞에 #을 붙이거나, FileZilla에서 파일 이름을 바꾸면 됩니다. 다시 켤 때는 반대로 합니다. (봇 멈추기 글)

    원본: crontab을 알아보자 · 더 쉬워진 세팅 6)

  9. 실제 봇 올리고 등록하기

    1. 봇 파일과 공통모듈은 /var/autobot에, 설정 yaml은 /home/ec2-user에 올립니다(5번 규칙).
    2. API 키를 넣고(주식 · 코인), 거래소·증권사 허용 IP에는 탄력적 IP를 등록합니다.
    3. 홈 폴더에서 python3 /var/autobot/봇파일.py로 한 번 실행해 오류가 없는지 봅니다.
    4. 코드 맨 위나 패키지 콘텐츠 가이드의 crontab 예시를 crontab -e로 등록합니다.
    5. 투자 비중과 주문 실행 여부를 확인합니다(2단계 9번과 같음).

    서버 하나에 봇 여러 개를 돌릴 수 있습니다. crontab 줄만 늘리면 됩니다. 봇이 많아지면 실행 시간 제한·중복 실행 방지가 필요합니다. → 서버 안정화

서버를 그만 쓸 때

서버(인스턴스)를 종료하고, 탄력적 IP도 해제하세요. 탄력적 IP는 해제하지 않으면 서버가 없어도 비용이 계속 나옵니다. 예전 Amazon Linux 2로 만든 서버를 옮길 때는 새 서버를 만들고 파일·crontab을 옮긴 뒤 탄력적 IP를 새 서버에 연결하면, 증권사·거래소에 등록한 IP를 그대로 쓸 수 있습니다.

자주 묻는 질문

서버 접속 창을 닫으면 봇이 멈추나요?

아닙니다. 접속은 서버를 들여다보는 창일 뿐이라, 창을 닫거나 내 PC를 꺼도 서버의 crontab과 봇은 계속 돕니다. 블로그에 글을 올린 뒤 로그아웃해도 글이 남아 있는 것과 같습니다.

crontab에 등록했는데 화면에 아무것도 안 나와요.

crontab 실행은 백그라운드라 접속 화면에는 보이지 않습니다. 메신저 알림이나 로그로 확인하세요. 봇 첫 부분에 실행 확인 메시지를 넣어 두면 '실행이 안 된 것'과 '조건이 안 맞아 매매가 없었던 것'을 구분할 수 있습니다.

서버 시간이 한국 시간과 다른가요?

네. AWS 서버는 UTC를 써서 한국보다 9시간 늦습니다. 한국 시간 오전 9시는 crontab에 0시로 적습니다. 게만아의 crontab 예시는 이 서버 시간 기준입니다.

서버 하나에 봇을 여러 개 돌려도 되나요?

네. crontab 줄을 늘리면 됩니다. 게만아도 서버 한 대에서 여러 봇을 돌립니다. 1분 주기 봇이 많아지면 실행 시간 제한과 중복 실행 방지를 함께 적용하세요.
